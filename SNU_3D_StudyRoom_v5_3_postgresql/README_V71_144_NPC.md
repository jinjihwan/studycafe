# V7.1: 144명의 가상 학습자 동적 운영

V6.9 행동형 튜토리얼을 유지하면서 NPC 일정·좌석·랭킹만 수정합니다. V7.0에서 도입했던 안내 메뉴와 대학 벽면 변경은 포함되지 않습니다.

## 핵심 운영 규칙

- 서울대/고려대/연세대: 학교별 고유 닉네임 48명, 전체 144명. **세 대학 전체에서 이름 중복 없음**.
- 첫 번째 방에서만 가상 학습자를 렌더링하고, 학교별 동시 최대 16명입니다. 실제 화면에는 해당 시각에 출석 중인 NPC만 생성합니다.
- 학교별 시간대 목표 (KST): 00~03 4~6명, 03~06 4~5명, 06~09 6~8명, 09~12 9~12명, 12~15 8~11명, 15~18 11~14명, 18~22 12~16명, 22~24 8~11명.
- 사람마다 다른 공부 시간 유형: 48명 중 10명 30분~2시간, 20명 2~5시간, 14명 5~8시간, 4명 8~10시간.
- 15분 단위로 하루 일정을 생성하며, **운영 날짜는 오전 6시~다음날 오전 6시**입니다. 새벽 00:00이 되어도 진행 중인 방문 일정은 끊지 않습니다.
- 공부 시간 집계는 **한국시간 00:00**에 새로 시작합니다. 출입·휴식 구간을 공부 시간에서 제외합니다.
- 일정은 학교·운영 날짜별 결정적 시드로 생성하므로 동일한 시각의 공부 계획은 서버 재시작 후에도 동일합니다.
- NPC의 입장·퇴장·이동·착석 상태와 좌석 잠금은 서버가 동기화합니다. 고정 NPC 전용 좌석은 없습니다.
- 실제 이용자가 예약하려는 의자에 NPC가 있으면 NPC는 다른 빈자리로 옮깁니다.
- 첫 번째 방은 **실제 이용자 최대 32명 + 가상 학습자 최대 16명**, 추가 방은 실제 이용자 48명이며 자동 방 생성·샤딩 구조는 유지합니다.
- 랭킹은 당일 실제 사용자 기록과 가상 학습자 144명의 계산 기록을 함께 정렬합니다. 한 페이지 20명씩 조회하며, 가상 학습자가 포함된다는 사실을 화면에 고지합니다.
- 사용자별 개인정보와 기록이 담긴 DB 테이블/마이그레이션은 변경하지 않습니다. 가상 학습자의 랭킹은 서버에서 결정적으로 계산하며 실제 사용자 기록으로 저장하지 않습니다.

## 설계상 제약

- 가상 학습자 출석·공부 기록은 **시뮬레이션 일정**이며, 이용자의 실측 공부 기록과 다릅니다.
- 시뮬레이션 공부 시간은 생성한 개인별 공부 구간을 기반으로 계산합니다. 실제 사람의 좌석 우선권 때문에 가상 학습자가 다른 자리로 옮기거나 입장을 못 할 수 있고, 이 경우 일시적으로 실제 3D 화면 출석자 수와 랭킹용 시뮬레이션 기록이 달라질 수 있습니다. 이 두 수치를 실제 사람의 접속/공부 기록과 혼동해서는 안 됩니다.
- 시간대별 인원 목표는 일정 생성 단계의 목표입니다. 30일 독립 시뮬레이션과 테스트에서 약 99.5% 구간을 충족했지만 **실제 좌석 점유로 인해 더 낮아질 수 있습니다**.
- 정식 운영 전 Android/iOS/PC 실제 브라우저에서 NPC 입퇴장 모션, 시점, 좌석 클릭, Google 로그인, PostgreSQL 환경을 직접 점검해야 합니다.
