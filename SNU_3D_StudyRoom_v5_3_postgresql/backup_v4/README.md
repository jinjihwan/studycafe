# 3D 스터디룸 v4 — 날짜별 영구 기록 / 내 기록 / 오늘의 랭킹

> 서울대학교 도서관을 참고한 **비공식** 3D 공간. 기존 v3의 Three.js 건축·가구·동물 후드 아바타·NPC 8명·착석·이동·카메라·채팅·초대 링크·서버 보안 검사를 보존했습니다. 새 UI는 기존 화면 위에 `내 기록` / `랭킹` 탭으로 추가됩니다.

## 설치와 실행 (모바일 GitHub Codespaces 기준)

**필요:** Node.js **22.13 이상**(권장 22.16+). Codespaces 터미널에서 실행할 수 있으며 PC가 필수는 아닙니다.

1. GitHub 저장소에 배포 ZIP을 업로드하고 Codespaces를 엽니다. 터미널에서 `ls`로 ZIP 파일명을 확인합니다.
2. ZIP을 풀고 해당 폴더로 이동합니다. 기존 v3 서버가 실행 중이면 먼저 그 터미널에서 `Ctrl+C`로 중지하세요.

   ```sh
   unzip SNU_3D_StudyRoom_v4.zip
   cd SNU_3D_StudyRoom_v4
   npm run check
   npm test
   npm start
   ```

3. `PORTS`에서 **3000** 포트를 엽니다. 친구와 동일 방에서 확인하려면 포트 Visibility를 **Public**으로 전환하고 `https://<주소>-3000.app.github.dev/?room=main` 링크를 공유하세요. Public 주소를 아는 사람은 접근할 수 있으므로 테스트할 때만 공개하세요.
4. 스마트폰에서 **도서관**, **내 기록**, **랭킹** 탭을 눌러 확인합니다. 오늘의 타이머는 의자에 앉으면 자동으로 시작하고, 일어나거나 일시정지하면 멈춥니다.
5. 동일 스마트폰에서 테스트하려면 Chrome 일반 탭과 시크릿 탭은 서로 다른 게스트로 취급됩니다. 같은 게스트인지 확인하려면 같은 브라우저의 다른 일반 탭을 사용하세요(한 번에 1개 연결만 활성화). 실제 2인 테스트는 친구의 다른 휴대폰 또는 다른 브라우저를 사용하세요.

**참고:** Three.js는 기존 v3의 jsDelivr CDN을 사용하므로 초기 3D 렌더링에는 인터넷 연결이 필요합니다. 다른 기기의 모바일 브라우저에서 외부 페이지를 열어야 WebGL 호환성을 검증할 수 있습니다.

### v3의 기존 게스트 ID 유지하기 (중요)

v3 서버에서 발급한 게스트 토큰은 해당 서버의 **`.guest-secret`**으로 서명되어 있습니다. **v3와 동일한 게스트 ID를 유지하려면** v3 Codespaces의 `.guest-secret`을 v4 루트에 안전하게 복사해야 합니다. 동일 저장소/Codespaces에서 v3가 `SNU_3D_StudyRoom_v3_stabilized` 폴더에 있고 v4를 별도 폴더로 압축 해제한 경우:

```sh
cp ../SNU_3D_StudyRoom_v3_stabilized/.guest-secret .guest-secret
chmod 600 .guest-secret
```

`cp` 실행은 **v4 폴더로 이동한 뒤** 수행합니다. 이전 `.guest-secret`이 없으면 이전 게스트 토큰은 검증할 수 없어 새 게스트가 발급됩니다. v3는 공부 기록을 영구 저장하지 않았으므로 **v3에서 이미 사라진 기록을 v4가 복구할 수는 없습니다.** 비밀키와 게스트 토큰은 공개 저장소에 업로드하거나 누구에게나 공유하지 마세요.

### 개발용 DB: SQLite (기본, 외부 서비스 가입 불필요)

`npm start`로 자동 생성되는 파일:

- `data/studyroom.sqlite`: 사용자·날짜별 공부 기록·랭킹 공개 설정
- `.guest-secret`: 게스트 토큰 서명 비밀키 (없을 때 자동 생성)

두 파일은 `.gitignore`에 포함되어 있으며 배포 ZIP에도 들어 있지 않습니다. 서버 프로세스를 재시작해도 같은 파일을 사용하면 기록이 보존됩니다. **Codespaces를 삭제하거나 새 Codespace를 만들면 로컬 DB/비밀키가 사라질 수 있으므로 신뢰할 수 있는 비공개 위치에 백업하세요.** 이 두 파일을 함께 보존해야 기존 게스트로 기록을 다시 볼 수 있습니다. SQLite는 한 대의 Node 서버를 사용하는 개발/소규모 운영용입니다. SQLite DB의 수동 복사는 서버가 종료된 상태에서 수행하세요(WAL 파일 동기화 문제 방지).

선택적으로 저장 위치를 변경할 수 있습니다:

```sh
STUDYROOM_DB_PATH=/workspaces/secure/studyroom.sqlite npm start
```

### 운영용 DB: PostgreSQL 14+ (선택 사항)

장기 운영에는 클라우드 PostgreSQL 공급자(예: Neon, Supabase, 자체 서버)에 **개인 PostgreSQL DB**를 먼저 생성하고 발급된 **DATABASE_URL**을 Codespaces Secret 또는 호스팅 제공자의 환경변수에 등록하세요. 클라이언트 코드나 공개 GitHub 저장소에 연결 문자열을 입력하지 마세요.

```sh
npm install
# DATABASE_URL, STUDYROOM_SECRET을 비공개 환경변수로 설정한 상태에서
npm start
```

- `npm install`은 PostgreSQL 클라이언트 `pg`를 설치합니다. SQLite만 사용할 경우 별도 패키지 설치가 필수는 아닙니다.
- `DATABASE_URL`이 설정되어 있으면 PostgreSQL을 사용합니다. 시작 시 `migrations/001_postgres.sql` 스키마가 idempotent하게 적용됩니다. SQLite 스키마는 `migrations/001_sqlite.sql`입니다.
- 운영 환경에서는 `STUDYROOM_SECRET`에 안전한 **32자 이상**의 고정 무작위 비밀키를 설정하세요. 이를 바꾸면 과거 게스트 토큰은 모두 무효가 됩니다.
- `STUDYROOM_PUBLIC_ORIGIN=https://실제-서비스-도메인` 설정으로 WebSocket/HTTP Origin을 제한할 수 있습니다. 프록시를 사용하는 운영 환경에서 명시하는 것을 권장합니다.
- PostgreSQL 데이터 자체를 사용하더라도 **방·좌석 잠금·접속자 상태는 현재 한 Node 프로세스의 메모리에서 관리**합니다. 서로 다른 Node 서버로 수평 확장하려면 Redis 등의 분산 좌석 잠금/방 상태 관리가 추가로 필요합니다.
- **PostgreSQL 실제 서비스 접속은 이 환경에서 검증하지 못했습니다.** 개발용 SQLite 파일 기반 서버/재시작 통합 테스트는 수행했습니다.

## v4 기능·데이터 구조

- `server/room.js`: 기존 좌석·접속·NPC 예약·이동·채팅·WebSocket 메시지 검사. 활성 서버 게스트는 1개 인스턴스만 유지(중복 입장은 이전 연결을 대체).
- `server/store.js`: 저장소 인터페이스와 SQLite/PostgreSQL 어댑터. 사용자 기록은 `guests` 및 `study_daily(guest_id, day, milliseconds)`에 저장합니다.
- `server/stats.js`: 한국시간 날짜별 요약, 월간 42칸 달력, 7일 데이터, 연속 일수, 랭킹 정렬.
- `client/dashboard.js`: 반응형 내 기록·랭킹·공개 설정·달력 UI. 기존 Three.js 코드는 변경하지 않고 신규 탭만 연결했습니다.
- `server/index.js`: REST API 및 기존 v3 WebSocket 서버. `backup_v3/`에 변경 전 파일을 보존했습니다.

**공부 시간 기록:** 서버만 착석/이동/시간을 결정합니다. 실시간 접속 중에는 `performance.now()`가 아니라 서버 경과시간으로 계산합니다. 한국시간 자정에 날짜를 분할합니다. 서버는 약 5초 단위로 변경 내역을 DB에 `increment`하여 매초 쓰지 않습니다. 종료(SIGTERM/SIGINT) 시 잔여 시간 저장을 시도합니다. 하드 크래시(SIGKILL/전원 오류) 시 **마지막 체크포인트 이후 최대 약 5초**가 유실될 수 있습니다. DB 장애 시 미저장 분량은 프로세스 메모리에 대기하고 복구 후 재시도하지만, DB 장애 중 프로세스도 소멸하면 이 시간은 복구할 수 없습니다.

**이동/좌석/탭:** 기존 v3 서버가 좌석 독점을 검증합니다. 기록 탭을 열거나 모바일 화면이 백그라운드에 있어도 **WebSocket 연결이 살아 있으면 시간은 계속 누적**됩니다. 연결이 실제로 끊기면 서버가 타이머를 일시정지하고 20초 동안 좌석을 보존합니다. 재접속한 동일 토큰은 잠시 유지된 좌석을 복원할 수 있지만, **일시정지된 타이머는 재개 버튼을 눌러야** 다시 증가합니다. 20초 후 완전 퇴장하면 좌석은 해제됩니다. 서버가 완전히 재시작되면 실시간 좌석은 초기화되며, DB 공부 기록은 유지됩니다.

**기록:** 오늘/어제/이번 주(월요일 시작)/이번 달/누적/연속 일수, 날짜별 캘린더(없는 날 0시간), 최근 7일 막대그래프. 연속 일수는 오늘 기록이 없으면 어제부터 계산합니다. 화면은 약 30초 간격 및 탭 복귀 시 갱신됩니다.

**랭킹:** 오늘 KST 00:00부터 공개 참여자의 누적 시간. NPC 제외. 20명 표시, 내 현재 순위 별도. 동일 기록은 **서버 게스트 ID 오름차순**을 동점 기준으로 사용합니다. 공개 설정을 끄면 다른 사람의 랭킹 조회에서 프로필/공부 시간 모두 사라지지만, 본인만 볼 수 있는 공부 기록은 남습니다. 서버 랭킹 결과는 최대 5초 캐시하고 활성 사용자의 서버 검증 미저장 시간으로 덮어써 업데이트합니다. 브라우저는 약 30초마다 조회합니다.

**게스트 한계:** 게스트 토큰은 브라우저 `localStorage`에 보존됩니다. 해당 데이터를 삭제하면 다른 사람이 아닌 **본인도** 옛 계정과 기록에 접근할 수 없을 수 있습니다. 토큰은 재접속 때 갱신되지만, 장기간 접속하지 않아 만료되면 복구할 수 없습니다. 소셜 로그인/계정 연결 및 안전한 소유권 이전은 v4에서 구현하지 않았습니다. 추후 구축할 때 기존 guest_id → account_id를 추가하는 DB 마이그레이션과 실소유자 재인증 절차가 필요합니다.

## API (클라이언트는 이 경로만 사용)

| API | 동작 |
|---|---|
| `POST /api/session` | 서명된 게스트 토큰 신규 발급 또는 갱신 (기존 v3 경로) |
| `GET /api/me/stats?month=YYYY-MM` | 내 공부 기록, 월 달력, 최근 7일 |
| `GET /api/ranking?limit=20` | 공개 참여자 오늘 랭킹, 내 순위 |
| `POST /api/me/privacy` | `{ "rankingPublic": false }` 공개 여부 변경 |
| `GET /health` | 서버 상태(저장 오류 포함) |

세 기록/랭킹 API 모두 `Authorization: Bearer <게스트 토큰>`을 검사하며 클라이언트가 임의의 `guest_id`나 공부 시간을 지정할 수 없습니다.

## 모바일 점검 절차

1. Codespaces에서 `npm run check && npm test` 실행 → 오류 0인지 확인.
2. `npm start` 후 `PORTS`의 3000 포트 URL을 엽니다. 기존 3D 공간·캐릭터 이동·회전·의자 착석을 확인합니다.
3. 착석 후 **내 기록** 탭을 열어 오늘 시간이 증가하는지 관찰합니다. 도서관으로 돌아왔을 때 머리 위 시계와 서버 시간도 맞는지 확인합니다.
4. 스마트폰 브라우저를 10초간 백그라운드로 보낸 뒤 복귀합니다. **연결이 유지되었다면** 공부 시간이 그만큼 증가합니다. 연결이 끊겼다면 타이머가 멈추고 재연결 후 재개가 필요합니다.
5. 친구의 스마트폰에서 같은 Public URL로 게스트 입장 → 각자 다른 좌석에 앉아 채팅하고 랭킹을 확인합니다. NPC는 랭킹에 없어야 합니다.
6. **내 기록** 하단의 ‘오늘의 공개 랭킹에 참여’를 끈 뒤 다른 기기의 랭킹에서 자신의 닉네임이 사라지는지 확인합니다. 내 기록은 남아야 합니다.
7. 서버를 `Ctrl+C`로 종료 후 같은 폴더에서 `npm start` → 동일 브라우저로 입장, 내 기록이 유지되는지 확인합니다.
8. 모바일 기기 FPS는 기존 `?room=main&perf=1` URL을 사용해 보세요. 화면 갱신 속도 및 장시간 발열은 실제 기기에서 측정해야 합니다.

**Codespaces는 24시간 서비스를 보장하는 상시 호스팅이 아닙니다.** Codespace가 정지되면 서버/웹소켓도 정지하며, SQLite 파일은 Codespace의 수명에 묶입니다. 장기 운영에는 영속 스토리지·관리형 PostgreSQL·항상 켜진 Node 서버·안전한 인증 키 보관 및 백업이 별도로 필요합니다.

## 자동 테스트

```sh
npm run check
npm test
```

`tests/multiplayer.test.js` + `tests/stability.test.js`는 기존 v3 테스트입니다. `tests/persistence.test.js`, `tests/v4-api.test.js`, `tests/restart.test.js`는 새 테스트입니다. 실행 결과는 `TEST_REPORT.md`와 `test-results.txt`를 참고하세요. 실제 PostgreSQL 서비스 연동, Chrome/Android/iOS의 WebGL UI, 장시간 온도/배터리는 자동 검증 완료로 표시하지 않았습니다.
